# RAG 项目面试问答指南

## 项目概述

### 一句话介绍
基于 RAG（检索增强生成）的 AI 客服系统，支持文档上传、知识库问答和流式对话。

### 技术栈
- **前端**：Vue 3 + TypeScript + Vite
- **后端**：Node.js + Express
- **AI 模型**：Claude Sonnet 4.5
- **向量数据库**：Pinecone（备选：内存存储）
- **核心技术**：RAG、Embedding、SSE 流式输出

## 核心面试问题（⭐⭐⭐⭐⭐ 必问）

### Q1: 什么是 RAG？为什么需要它？

**回答**：
> RAG（Retrieval-Augmented Generation，检索增强生成）是一种结合了**信息检索**和**生成式 AI** 的技术。
> 
> **核心问题**：
> - AI 模型只知道训练数据（截止时间之前的知识）
> - 不知道企业私有数据、最新信息、特定领域知识
> 
> **RAG 的解决方案**：
> ```
> 用户问题 → 从知识库检索相关信息 → 拼接到 Prompt 中 → AI 基于检索内容生成回答
> ```
> 
> **优势**：
> - ✅ 降低幻觉（AI 基于真实文档回答）
> - ✅ 知识可更新（无需重新训练模型）
> - ✅ 可追溯来源（知道答案来自哪个文档）

**加分回答**：
> 我在项目中实现了完整的 RAG 流程：
> - 文档处理：PDF 解析 → 文本切片（500 字 + 50 字重叠）
> - 向量化：Embedding 转换为 1536 维向量
> - 检索：余弦相似度计算 Top-K 相关文档
> - 生成：拼接上下文 + 问题，调用 Claude API

---

### Q2: RAG 的完整工作流程是什么？

**回答**：
> **阶段 1：文档处理（离线）**
> ```
> 1. 上传文档（PDF/Word/TXT）
> 2. 文本提取（pdf-parse）
> 3. 文本切片（Chunking）
>    - 块大小：500 字
>    - 重叠：50 字（保证语义连贯）
> 4. 向量化（Embedding）
>    - 每个文本块 → 1536 维向量
> 5. 存储到向量数据库（Pinecone）
> ```
> 
> **阶段 2：用户查询（在线）**
> ```
> 1. 用户提问
> 2. 问题向量化（同样的 Embedding 模型）
> 3. 语义搜索
>    - 计算问题向量与所有文档向量的相似度
>    - 返回 Top-3 最相关的文档块
> 4. 拼接 Prompt
>    "参考信息：[检索到的文档]
>     用户问题：[原始问题]
>     请根据参考信息回答。"
> 5. 调用 AI 生成回答
> 6. 流式输出给用户
> ```

**示例代码**：
```javascript
// 步骤 1：向量化问题
const queryEmbedding = await getEmbedding(userQuestion);

// 步骤 2：检索相关文档
const results = await searchSimilarDocs(queryEmbedding, topK=3);

// 步骤 3：拼接 Prompt
const context = results.map(r => r.text).join('\n\n');
const prompt = `参考信息：\n${context}\n\n用户问题：${userQuestion}`;

// 步骤 4：生成回答
const answer = await claude.generate(prompt);
```

### Q3: 什么是 Embedding（向量化）？为什么需要它？

**回答**：
> **Embedding 是什么？**
> - 把文本转换为**高维向量**（数字数组）
> - 语义相近的文本 → 向量相近
> 
> **为什么需要？**
> ```
> 传统关键词搜索：
> 用户问："如何退货？"
> 搜索关键词："退货"
> ❌ 找不到文档（文档里写的是"退款流程"）
> 
> 语义搜索（Embedding）：
> "如何退货？" → [0.234, -0.567, ...]
> "退款流程" → [0.221, -0.543, ...]
> ✅ 相似度 0.85，成功匹配！
> ```
> 
> **技术细节**：
> - 维度：1536（OpenAI text-embedding-3-small）
> - 相似度计算：余弦相似度
> - 范围：-1 到 1（越接近 1 越相似）

**加分回答**：
> 我的项目中实现了模拟 Embedding：
> ```javascript
> function generateMockEmbedding(text) {
>   // 使用文本内容作为种子
>   let seed = 0;
>   for (let i = 0; i < text.length; i++) {
>     seed += text.charCodeAt(i);
>   }
>   
>   // 生成 1536 维向量
>   const vector = [];
>   for (let i = 0; i < 1536; i++) {
>     seed = (seed * 9301 + 49297) % 233280;
>     vector.push((seed / 233280.0 - 0.5) * 2);
>   }
>   
>   // 归一化
>   return normalize(vector);
> }
> ```
> 
> 生产环境会使用 OpenAI API 或开源模型（BGE-M3）。

### Q4: 文本切片（Chunking）的原理和最佳实践？

**回答**：
> **为什么需要切片？**
> - AI 有 token 限制（不能把整本书发给 AI）
> - 检索精度：小块更精准
> 
> **核心参数**：
> 
> **1. chunkSize（块大小）**
> - 我的项目：500 字
> - 行业经验：300-800 字
> - 过小：语义不完整
> - 过大：无关信息多
> 
> **2. overlap（重叠）**
> - 我的项目：50 字
> - 为什么需要？保证语义连贯
> 
> **示例**：
> ```
> 原文："...他有 5 年 Vue 经验。从 2019 年开始..."
>                           ↑ 切断点
> 
> 无重叠：
> 块 1: "...他有 5 年 Vue 经验。"
> 块 2: "从 2019 年开始..."  ← 上下文丢失
> 
> 有 50 字重叠：
> 块 1: "...他有 5 年 Vue 经验。从 2019 年开始..."
> 块 2: "...他有 5 年 Vue 经验。从 2019 年开始..."
>       ↑ 重叠部分保证了语义连贯
> ```

**代码实现**：
```javascript
function chunkText(text, chunkSize = 500, overlap = 50) {
  const chunks = [];
  let start = 0;
  
  while (start < text.length) {
    const end = start + chunkSize;
    chunks.push(text.slice(start, end));
    start = end - overlap;  // 下一块回退 overlap
  }
  
  return chunks;
}
```

### Q5: 向量数据库是什么？为什么不用 MySQL？

**回答**：
> **向量数据库的核心功能**：
> - 存储高维向量（1536 维）
> - 高效计算相似度（百万级数据，毫秒级响应）
> 
> **为什么不用 MySQL？**
> ```
> MySQL：
> - 存储：表格数据（行和列）
> - 查询：WHERE age > 18（精确匹配）
> - ❌ 无法高效计算向量相似度
> 
> 向量数据库（Pinecone/Qdrant）：
> - 存储：向量 + 元数据
> - 查询：找最相似的 K 个向量
> - ✅ ANN（近似最近邻）算法，毫秒级
> ```
> 
> **技术对比**：
> 
> | 数据库 | 类型 | 优点 | 缺点 |
> |--------|------|------|------|
> | **Pinecone** | 托管服务 | 简单、免费额度 | 依赖外部 |
> | **Qdrant** | 开源 | 可自部署、免费 | 需维护 |
> | **Milvus** | 开源 | 企业级、高性能 | 复杂 |

**加分回答**：
> 我的项目实现了**双存储架构**：
> - **内存存储**：开发/演示环境，快速迭代
> - **Pinecone**：生产环境，持久化 + 高性能
> 
> 容错设计：Pinecone 失败自动降级到内存检索。

### Q6: 余弦相似度是如何计算的？

**回答**：
> **公式**：
> ```
> cosine_similarity(A, B) = (A · B) / (|A| × |B|)
> 
> 其中：
> - A · B：向量点积（对应元素相乘再求和）
> - |A|：向量 A 的模长（各元素平方和再开方）
> ```
> 
> **为什么用余弦相似度？**
> - 只关心**方向**，不关心**大小**
> - 适合归一化后的向量（Embedding 通常已归一化）
> - 范围：-1 到 1（1 表示完全相同）
> 
> **代码实现**：
> ```javascript
> function cosineSimilarity(vecA, vecB) {
>   let dotProduct = 0;
>   let normA = 0;
>   let normB = 0;
>   
>   for (let i = 0; i < vecA.length; i++) {
>     dotProduct += vecA[i] * vecB[i];
>     normA += vecA[i] * vecA[i];
>     normB += vecB[i] * vecB[i];
>   }
>   
>   return dotProduct / (Math.sqrt(normA) * Math.sqrt(normB));
> }
> ```

**示例**：
```
问题："魏仁杰的手机号？"     → [0.8, 0.6]
文档 1："姓名魏仁杰，19983485600" → [0.9, 0.5]
文档 2："工作经历..."           → [0.2, 0.1]

相似度 1 = 0.99（非常相关）✅
相似度 2 = 0.18（不相关）❌
```

## 中等难度面试问题（⭐⭐⭐⭐）

### Q7: RAG 和微调（Fine-tuning）的区别？

**回答**：
> | 维度 | RAG | 微调 |
> |------|-----|------|
> | **知识来源** | 外部文档（检索） | 模型参数（训练） |
> | **更新成本** | ✅ 低（上传新文档） | ❌ 高（重新训练） |
> | **适用场景** | 动态知识、企业数据 | 特定任务、风格 |
> | **可解释性** | ✅ 可追溯来源 | ❌ 黑盒 |
> | **成本** | ✅ 低 | ❌ 高（GPU） |
> 
> **结合使用**：
> - 微调：调整 AI 的回答风格、语气
> - RAG：提供最新的、特定的知识

### Q8: 如何优化 RAG 的检索准确率？

**回答**：
> **1. 优化文本切片**
> - 动态块大小（根据段落自然分割）
> - 增加重叠（50 → 100 字）
> 
> **2. 优化 Embedding**
> - 使用领域专用模型（如医疗、法律）
> - 中文场景用 BGE-M3
> 
> **3. 混合检索（Hybrid Search）**
> - 语义检索（Embedding）+ 关键词检索（BM25）
> - 加权融合两种结果
> 
> **4. 重排序（Reranking）**
> - 初筛：检索 Top-10
> - 精排：用更强的模型重新排序，返回 Top-3
> 
> **5. 查询改写（Query Rewriting）**
> - 用 AI 把模糊问题改写成精确查询
> - 例："他的电话"→"魏仁杰的手机号码"

### Q9: RAG 系统如何处理多轮对话？

**回答**：
> **挑战**：
> - 用户："他会 Vue 吗？"（"他"指谁？）
> - 需要上下文理解
> 
> **解决方案**：
> 
> **1. 对话历史拼接**
> ```javascript
> const context = [

>   "用户：他会 Vue 吗？"  // 当前问题
> ].join('\n');
> 
> // 检索时用完整上下文
> const results = await search(context);
> ```
> 
> **2. 查询改写**
> ```
> 原问题："他会 Vue 吗？"
>   ↓ AI 改写
> 新问题："魏仁杰会 Vue 吗？"
> ```
> 
> **3. 会话级缓存**
> - 缓存已检索的文档
> - 后续问题优先从缓存查找

## 项目亮点（⭐⭐⭐⭐⭐ 面试加分项）

### 1. 双存储架构（容错设计）

**设计思路**：
```
文档向量 → 同时存储到：
           ├─ 内存（必定成功）
           └─ Pinecone（可能失败）

检索时：
  ├─ 优先 Pinecone
  └─ 失败自动降级到内存
```

**优势**：
- ✅ 高可用：外部服务故障不影响功能
- ✅ 灵活：开发用内存，生产用 Pinecone
- ✅ 性能：内存检索极快（< 1ms）

---

### 2. 流式输出优化

**技术方案**：
- SSE（Server-Sent Events）
- 模拟流式（第三方 API 不支持真实流式）
- 每 30ms 发送 2 个字符，制造打字机效果

**代码实现**：
```javascript
for (let i = 0; i < fullText.length; i += 2) {
  const chunk = fullText.slice(i, i + 2);
  res.write(`data: ${JSON.stringify({ text: chunk })}\n\n`);
  await new Promise(resolve => setTimeout(resolve, 30));
}
```

---

### 3. 完整的错误处理

- ✅ PDF 解析失败 → 提示支持的格式
- ✅ Embedding 失败 → 使用模拟向量
- ✅ Pinecone 失败 → 降级到内存
- ✅ 检索无结果 → AI 回复"根据现有信息无法回答"

## 技术深度问题（⭐⭐⭐⭐⭐ 资深岗位）

### Q10: 如何评估 RAG 系统的效果？

**回答**：
> **指标体系**：
> 
> **1. 检索质量（Retrieval Quality）**
> - **Recall@K**：Top-K 中包含正确文档的比例
> - **MRR（平均倒数排名）**：正确文档的平均排名
> 
> **2. 生成质量（Generation Quality）**
> - **准确性**：答案是否正确
> - **相关性**：答案是否基于检索内容
> - **幻觉率**：AI 编造信息的比例
> 
> **3. 端到端指标**
> - **用户满意度**：点赞/点踩比例
> - **响应时间**：P95 延迟 < 2s
> 
> **评估方法**：
> ```python
> # 准备测试集
> test_cases = [
>   {"question": "魏仁杰的手机号？", "expected": "19983485600"},
>   {"question": "他会 Vue 吗？", "expected_keywords": ["Vue", "5年"]},
> ]
> 
> # 自动化评估
> for case in test_cases:
>   results = rag_search(case["question"])
>   answer = generate_answer(results)
>   
>   # 检查答案是否包含关键信息
>   score = evaluate(answer, case["expected"])
> ```
